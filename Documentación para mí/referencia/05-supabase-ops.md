# Referencia de Supabase OPS y configuración

El panel administrativo se autentica en el runtime y usa proxies para hablar con OPS. OPS distingue la autorización interna y el acceso de un usuario de su propio proyecto. Aquí se describen los archivos que controlan deploy, registro de artefactos, catálogos de soporte y telemetría.

## Configuración y archivos auxiliares

- Ignora ramas y .temp del proyecto local y archivos de variables de desarrollo de dotenvx. Reduce artefactos de CLI y secretos locales en el historial. [`runtime/.gitignore`](../../apps/referidos-app/supabase/.gitignore)
- Define el proyecto runtime local, API, Postgres, Auth, Realtime, Storage y Edge Functions. Habilita custom_access_token_hook y declara configuración de gateway para varias funciones. El bloque de seed señala ./seed.sql, que no figura entre los archivos del checkout. [`runtime/config.toml`](../../apps/referidos-app/supabase/config.toml)
- Seed histórico con inserts para el esquema original de usuarios, negocios y promociones. Sirve para entender fixtures antiguas y contiene valores que parecen datos de contacto; conviene sustituirlos por ejemplos sintéticos antes de reutilizarlo. [`runtime/seed.old`](../../apps/referidos-app/supabase/seed.old)
- Seed histórico ampliado con escaneos, comentarios y reportes además de las entidades base. Las migraciones posteriores cambiaron columnas e IDs, por lo que debe cotejarse con el esquema actual y revisar los valores que parecen datos de contacto. [`runtime/seed1.old`](../../apps/referidos-app/supabase/seed1.old)
- Runbook de OPS con separación de proyectos, variables necesarias por nombre, funciones principales y pasos de mantenimiento. Documenta que el panel de la PWA usa un bridge. [`OPS/README.md`](../../apps/referidos-ops/README.md)
- Define API y Postgres OPS locales con puertos propios, Auth, Edge Runtime y flags por función. Mantiene migraciones activas y seed desactivado, así el proyecto puede prepararse junto al runtime sin compartir configuración local. [`OPS/supabase/config.toml`](../../apps/referidos-ops/supabase/config.toml)
- Marcador generado por Supabase CLI para la versión disponible de la herramienta. Es metadato local del cliente, separado del estado de las migraciones. [`OPS/supabase/.temp/cli-latest`](../../apps/referidos-ops/supabase/.temp/cli-latest)
- Registra versión observada del servicio Auth al enlazar el proyecto. Diagnostica diferencias de herramientas y ambiente sin definir políticas Auth. [`OPS/supabase/.temp/gotrue-version`](../../apps/referidos-ops/supabase/.temp/gotrue-version)
- Metadato de conexión del pooler generado por la CLI. Utiliza la configuración de cuenta autorizada para acceder y evita copiar cadenas de conexión a documentación compartida. [`OPS/supabase/.temp/pooler-url`](../../apps/referidos-ops/supabase/.temp/pooler-url)
- Registra versión de Postgres detectada por la CLI para el enlace. La versión local se especifica aparte en config.toml. [`OPS/supabase/.temp/postgres-version`](../../apps/referidos-ops/supabase/.temp/postgres-version)
- Registra qué referencia quedó enlazada para comandos de CLI. Comprueba el destino antes de cualquier operación remota, pues un archivo de enlace puede quedar antiguo. [`OPS/supabase/.temp/project-ref`](../../apps/referidos-ops/supabase/.temp/project-ref)
- Marcador de versión del servicio REST. Es diagnóstico del enlace y no contiene el contrato de endpoints. [`OPS/supabase/.temp/rest-version`](../../apps/referidos-ops/supabase/.temp/rest-version)
- Marcador de migración de Storage reportado por la plataforma en el último enlace. Es independiente del historial SQL del producto. [`OPS/supabase/.temp/storage-migration`](../../apps/referidos-ops/supabase/.temp/storage-migration)
- Marcador de la versión del servicio de Storage reportado por la plataforma. El registro de artefactos se define en sus migraciones y funciones. [`OPS/supabase/.temp/storage-version`](../../apps/referidos-ops/supabase/.temp/storage-version)

## Edge Functions y helpers

### Integración y utilidades de servidor

- Concentra resolución del repositorio y autenticación GitHub, prefiere token de instalación de GitHub App cuando puede generarlo y conserva fallback a PAT. Normaliza la clave privada de distintos formatos sin trasladarla al cliente. Lo usan los workflows que necesita iniciar o consultar OPS. [`_shared/github-auth.ts`](../../apps/referidos-ops/supabase/functions/_shared/github-auth.ts)
- Inicializa clientes público y de servidor para el proyecto OPS, añade utilidades de respuesta y autenticación y resuelve perfil por id_auth. Los handlers deciden si aceptan una operación interna o un usuario admin. [`_shared/support.ts`](../../apps/referidos-ops/supabase/functions/_shared/support.ts)

### Catálogos de soporte y telemetría

- Administra el registro de aplicaciones. Admite lista, alta, cambios, activación y limpieza. Resuelve tenant y normaliza aliases y origen antes de escribir para que cada runtime reciba una identidad estable. [`ops-support-apps-admin/index.ts`](../../apps/referidos-ops/supabase/functions/ops-support-apps-admin/index.ts)
- Fija verify_jwt = false para este endpoint y deja al handler distinguir la llamada interna autenticada del usuario admin. El ajuste también se declara en el TOML principal. [`ops-support-apps-admin/config.toml`](../../apps/referidos-ops/supabase/functions/ops-support-apps-admin/config.toml)
- CRUD de categorías y macros con operaciones explícitas de estado. Valida el ámbito, verifica categorías y normaliza códigos, audiencia, estados y destinos. Los triggers del esquema producen los deltas que consumen los runtimes. [`ops-support-macros-admin/index.ts`](../../apps/referidos-ops/supabase/functions/ops-support-macros-admin/index.ts)
- Fija verify_jwt = false para el endpoint de macros. La autorización real del actor y del tenant se comprueba en su implementación. [`ops-support-macros-admin/config.toml`](../../apps/referidos-ops/supabase/functions/ops-support-macros-admin/config.toml)
- Lee el log de cambios del catálogo por tenant y after_seq con tamaño acotado. Autoriza proxy o administrador según el canal y devuelve lotes ordenados para que el runtime avance su cursor sin copiar todo cada vez. [`ops-support-macros-sync/index.ts`](../../apps/referidos-ops/supabase/functions/ops-support-macros-sync/index.ts)
- Valida token de operación, proyecto de origen permitido y tamaño del lote. Llama a ops_telemetry_ingest_batch y devuelve resultados por elemento. Conserva la frontera de escritura de telemetría en OPS. [`ops-telemetry-ingest/index.ts`](../../apps/referidos-ops/supabase/functions/ops-telemetry-ingest/index.ts)

### Versionado y despliegue

- Lee archivos y commits del repositorio y reglas del catálogo para clasificar el cambio y sugerir bump y semver. La vista previa ayuda a elegir la release antes de disparar la compilación. [`versioning-dev-release-preview/index.ts`](../../apps/referidos-ops/supabase/functions/versioning-dev-release-preview/index.ts)
- Recibe operaciones dispatch y status para el workflow dev. Admite creación de release y backfill de artefacto, valida producto, referencia y release según el modo, y registra auditoría. Permite que el panel siga la ejecución al salir de la petición HTTP inicial. [`versioning-dev-release-create/index.ts`](../../apps/referidos-ops/supabase/functions/versioning-dev-release-create/index.ts)
- Resuelve release y destino, obtiene migraciones requeridas de cambios registrados y consulta el inventario runtime. También coordina el workflow de aplicar migraciones cuando se pide y registra validaciones de entorno. Cubre dependencias de DB y configuración antes de sacar una release. [`versioning-release-gate/index.ts`](../../apps/referidos-ops/supabase/functions/versioning-release-gate/index.ts)
- Fija verify_jwt = false para dejar las comprobaciones internas o de admin a los flujos que consumen el gate. No define qué actor puede aprobar o aplicar. [`versioning-release-gate/config.toml`](../../apps/referidos-ops/supabase/functions/versioning-release-gate/config.toml)
- Coordina ramas y PRs de release y el paquete de workflows de CI. Puede leer checks, crear, refrescar, comentar, cerrar o fusionar el PR autorizado, y sincronizar workflows bajo las condiciones que determina el handler. Permite preparar el commit de destino que después comprueba el ejecutor. [`versioning-release-sync/index.ts`](../../apps/referidos-ops/supabase/functions/versioning-release-sync/index.ts)
- Fija verify_jwt = false; el handler identifica admin de OPS o credencial del proxy. El acceso a GitHub se resuelve en el servidor. [`versioning-release-sync/config.toml`](../../apps/referidos-ops/supabase/functions/versioning-release-sync/config.toml)
- Resuelve la solicitud aprobada, comprueba archivo y commit asociados a release, rama destino y gate de migración. Las operaciones dispatch y status permiten disparar y seguir el workflow. Guarda el estado inicial por RPC y se apoya en callback para el resultado. [`versioning-deploy-execute/index.ts`](../../apps/referidos-ops/supabase/functions/versioning-deploy-execute/index.ts)
- Valida callback, asocia el evento al intento y registra inicio o resultado. Finaliza datos de release, versión de configuración y artefacto por entorno, y coordina limpieza y sync de release a observabilidad cuando procede. El pipeline devuelve así el estado concreto de la publicación a OPS. [`versioning-deploy-callback/index.ts`](../../apps/referidos-ops/supabase/functions/versioning-deploy-callback/index.ts)
- Registra y lista artefactos, nodos y solicitudes, admite heartbeat, cancelación y finalización, y genera URLs firmadas de Storage. El workflow y las máquinas locales pueden reconciliar su inventario por release sin acceso público al bucket. [`versioning-artifact-sync/index.ts`](../../apps/referidos-ops/supabase/functions/versioning-artifact-sync/index.ts)
