# Referencia de Edge Functions del runtime

Cada carpeta dentro de `apps/referidos-app/supabase/functions` tiene un endpoint separado. Las secciones siguen los flujos del usuario. Usa `index.ts` como punto de entrada, sigue la inicialización y validación, luego las llamadas a datos y la respuesta. Una llamada a `supabaseAdmin` opera como backend privilegiado y exige que el handler valide el actor y el recurso cuando corresponda.

La configuración de gateway aparece en el TOML principal y, para algunas funciones, en un TOML local. `verify_jwt = false` elimina la verificación automática de ese gateway. La autenticación y autorización aplicable depende del código del endpoint, del propósito del canal y de la configuración desplegada. El inventario describe el checkout local. [TOML principal](../../apps/referidos-app/supabase/config.toml)

## Código compartido

- Normalización común de proveedores. parseLabel y buildDisplayParts separan calle y divisiones territoriales, loadTerritories contrasta con provincias, cantones y parroquias y los métodos por proveedor adaptan el formato. Ambas direcciones usan este archivo para guardar y mostrar datos coherentes. [`_shared/addressNormalize.ts`](../../apps/referidos-app/supabase/functions/_shared/addressNormalize.ts)
- Núcleo de utilidades de eventos. Resuelve identidad y tenant, normaliza nivel y origen, sanea cadenas, enmascara correo y teléfono, recorta adjuntos y procesa frames. Cambiar los campos admitidos aquí afecta a ingesta, symbolication, policy y otros endpoints que comparten el filtrado. [`_shared/observability.ts`](../../apps/referidos-app/supabase/functions/_shared/observability.ts)
- Parsea Bearer y session_id, valida usuario con Auth, verifica en user_session_devices si la sesión sigue activa, normaliza IDs de dispositivo y llama a la limpieza. Reúne el contrato de sesiones para que registro, lista y revocación comprueben el mismo modelo. [`_shared/session.ts`](../../apps/referidos-app/supabase/functions/_shared/session.ts)
- Inicializa clientes de Supabase con privilegios apropiados a cada tarea, compone CORS y JSON, valida tokens, recobra perfiles y flags y normaliza la categoría. Lo importan muchos handlers de soporte, admin y OPS. El helper de autenticación resuelve identidad, y cada handler decide qué rol y recurso puede usar. [`_shared/support.ts`](../../apps/referidos-app/supabase/functions/_shared/support.ts)
- Adapta aliases históricos y consulta support_resolve_app_identity en el catálogo runtime. Devuelve canal y aplicación normalizados para que tickets e informes sigan usando un ID consistente cuando cambie una etiqueta. [`_shared/supportAppIdentity.ts`](../../apps/referidos-app/supabase/functions/_shared/supportAppIdentity.ts)
- Motor de asignación compartido. Lee flags, agentes, jornadas y capacidad; aplica transiciones por tiempo, elige candidatos para cola general o personal y registra asignaciones y eventos. La lógica vive aquí porque altas, pings, cierres y cambios manuales afectan la misma cola. [`_shared/supportAutoAssign.ts`](../../apps/referidos-app/supabase/functions/_shared/supportAutoAssign.ts)
- Traduce estructuras antiguas de logs a eventos sanitizados de soporte y los reenvía a obs-ingest conservando autenticación. Centraliza mapeo de campos y lotes para los alias log-event y support-log-event. [`_shared/supportLogBridge.ts`](../../apps/referidos-app/supabase/functions/_shared/supportLogBridge.ts)
- Lee macros y categorías cacheadas, normaliza app, audiencia y códigos, y arma la lista pública de categorías según macros publicadas. El formulario público y la creación del ticket comparten así el criterio de qué categoría se puede ofrecer. [`_shared/supportMacroCatalog.ts`](../../apps/referidos-app/supabase/functions/_shared/supportMacroCatalog.ts)

## Identidad, altas y sesiones

- Resuelve el perfil y las relaciones de negocio para el usuario autenticado. Contrasta datos de Auth, estado de cuenta y dependencias necesarias, sincroniza señales de identidad cuando procede y devuelve allowAccess, reasons y datos para decidir qué pantalla seguir. Permite que web y Android compartan la decisión de entrada. [`onboarding/index.ts`](../../apps/referidos-app/supabase/functions/onboarding/index.ts)
- Valida completitud de cliente o negocio desde el perfil autenticado. Comprueba requisitos de dirección y sucursales, y activa el perfil y las filas de negocio aplicables cuando el alta alcanza el estado válido. Es el paso que convierte un formulario parcial en una cuenta utilizable. [`validate-registration/index.ts`](../../apps/referidos-app/supabase/functions/validate-registration/index.ts)
- Verifica sesión y rol autorizado. Genera un código único con destino de rol y parámetros de vigencia, y registra su creador en codigos_registro. Es la entrada administrativa del mecanismo de invitación. [`create-registration-code/index.ts`](../../apps/referidos-app/supabase/functions/create-registration-code/index.ts)
- Lista entradas de codigos_registro para roles habilitados con filtros y paginación. Separa la vista administrativa de códigos del flujo del solicitante. [`list-registration-codes/index.ts`](../../apps/referidos-app/supabase/functions/list-registration-codes/index.ts)
- Resuelve el actor autorizado y revoca un registro en codigos_registro. Cambiar su estado conserva antecedentes de emisión y evita gestionar vigencia desde la interfaz. [`revoke-registration-code/index.ts`](../../apps/referidos-app/supabase/functions/revoke-registration-code/index.ts)
- Valida el token de usuario y comprueba código, rol esperado, revocación, vencimiento y estado de uso. Permite validación previa con consume desactivado. En modo consumo vincula su uso al usuario para impedir que el registro se dé por válido solo en pantalla. [`validate-registration-code/index.ts`](../../apps/referidos-app/supabase/functions/validate-registration-code/index.ts)
- Autentica al llamante y usa Auth Admin para establecer la contraseña de su propio usuario cuando el flujo lo permite. Centraliza las comprobaciones del cambio y la interacción con el proveedor de identidad. [`set-password/index.ts`](../../apps/referidos-app/supabase/functions/set-password/index.ts)
- Valida la identidad, localiza perfil y negocios vinculados y ejecuta el borrado de registros y cuenta de Auth. Para cualquier cambio, revisa dependencias SQL y qué pasa si una fase falla, dado que Auth y Postgres atraviesan límites de operación distintos. [`delete-account/index.ts`](../../apps/referidos-app/supabase/functions/delete-account/index.ts)
- Autentica el JWT y extrae la sesión. Registra o refresca dispositivo, plataforma, etiqueta y señal de agente de usuario, deduplica sesiones según el dispositivo y prunea registros. El registro hace posible inventariar y revocar dispositivos sin confundirlos con el perfil. [`session-register/index.ts`](../../apps/referidos-app/supabase/functions/session-register/index.ts)
- Lista filas de user_session_devices para el usuario autenticado y marca la sesión actual. Devuelve nombres legibles para la UI de seguridad. [`session-list/index.ts`](../../apps/referidos-app/supabase/functions/session-list/index.ts)
- Valida sesión activa y titularidad, y marca una sesión concreta como revocada. La tabla de sesiones permite que las políticas y el bootstrap apliquen esa decisión. [`session-revoke/index.ts`](../../apps/referidos-app/supabase/functions/session-revoke/index.ts)
- Marca sesiones del mismo usuario en conjunto bajo la validación de la sesión actual. Soporta la acción de cerrar dispositivos desde seguridad sin que el cliente pueda modificar arbitrariamente las filas. [`session-revoke-all/index.ts`](../../apps/referidos-app/supabase/functions/session-revoke-all/index.ts)
