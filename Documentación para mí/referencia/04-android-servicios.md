## Contrato de datos

Android utiliza tres caminos hacia el runtime. El SDK creado por `mobileApi.ts` agrupa funciones por dominio y suele devolver un resultado normalizado. Las consultas de tablas usan el cliente de Supabase con la sesión de la persona. Las mutaciones operativas, como resolver un ticket o pedir una promoción de release, pasan por acciones del runtime o un proxy. Antes de cambiar una firma, rastrea tanto pantalla → servicio como servicio → tabla, RPC o función. [Cliente de Android](../../apps/referidos-android/src/shared/services/mobileApi.ts) · [SDK API compartido](../../packages/api-client/src/createMobileApi.js)

| Archivo | Qué hace y por qué existe |
|---|---|
| [mobileApi.ts](../../apps/referidos-android/src/shared/services/mobileApi.ts) | Valida las variables al importar, crea un único cliente Supabase, compone `mobileApi` y conecta el SDK de observabilidad con contexto Android. Concentra la configuración para que las pantallas no creen clientes separados. El API compartido tiene una importación local que conviene comprobar desde un checkout nuevo. |
| [entityQueries.ts](../../apps/referidos-android/src/shared/services/entityQueries.ts) | Accede a usuarios, negocios, sucursales, promos, historial QR, tickets y eventos. `maybeSingleByAnyColumn` y `listByAnyColumn` prueban nombres históricos cuando falta una columna. Centraliza las mutaciones de promos/sucursales, el vínculo `promos_sucursales` y el RPC `redeem_valid_qr`. También ofrece normalizadores de fechas/estados y el selector `readFirst` para registros heterogéneos. |
| [accountLifecycle.ts](../../apps/referidos-android/src/shared/services/accountLifecycle.ts) | Invoca `delete-account` con la sesión actual y convierte la respuesta en estado útil para los perfiles. La política y el efecto de esta operación se implementan dentro de la Edge Function de Supabase. |
| [sessionDevices.ts](../../apps/referidos-android/src/shared/services/sessionDevices.ts) | Crea o conserva el identificador de dispositivo local, llama funciones para registrar, listar y revocar sesiones, interpreta errores de Edge Functions y forma filas de dispositivo/actividad para la vista. El registro aquí se usa desde el panel de sesiones. |
| [appNotifications.ts](../../apps/referidos-android/src/shared/services/appNotifications.ts) | Consulta `app_notifications`, normaliza los roles y llama las RPC para marcar como leída una selección o un scope. Guarda preferencias de temas en AsyncStorage. Centraliza políticas de frecuencia, con modo híbrido para admin/soporte y carga por montaje para cliente/negocio. |
| [adminOps.ts](../../apps/referidos-android/src/shared/services/adminOps.ts) | Lee y cuenta tablas para administración, con adaptación a columnas existentes. Centraliza las llamadas autenticadas de reportes y métricas Prelaunch y las consultas de eventos/issues. Recupera el access token de la sesión antes de invocar operaciones que lo requieren. |
| [supportDeskQueries.ts](../../apps/referidos-android/src/shared/services/supportDeskQueries.ts) | Lee la vista `support_threads_inbox`, con fallback a la tabla de hilos si el esquema esperado falta. Consulta ficha, notas, eventos, agente, jornadas, issues, dashboard y catálogo de errores. Normaliza campos y combina resultados para evitar repetir lógica operativa en el perfil y en el admin. |
| [supportCatalog.ts](../../apps/referidos-android/src/shared/services/supportCatalog.ts) | Lee `support_macro_categories_cache` y `support_macros_cache`, normaliza nombres, estados y audiencias. Filtra macros por entorno, app, rol, estado y categoría antes de presentarlas. Permite usar la copia del runtime sin acoplar los dispositivos al control OPS. |
| [supportOps.ts](../../apps/referidos-android/src/shared/services/supportOps.ts) | Envuelve `support-ops-proxy` para apps, macros/categorías, estados y edición. Incluye el disparo de sincronizaciones de apps y macros al runtime y funciones autenticadas para listar, crear y revocar códigos de registro. |
| [supportRuntimeFlags.ts](../../apps/referidos-android/src/shared/services/supportRuntimeFlags.ts) | Carga y normaliza la fila de configuración en `support_runtime_flags`, conserva una copia y notifica a suscriptores locales. Expone cambios de permisos de sesión/jornada, autoasignación y otros valores operativos que usan los paneles de soporte. |
| [systemFeatureFlags.ts](../../apps/referidos-android/src/shared/services/systemFeatureFlags.ts) | Persiste flags del sistema en AsyncStorage, inicializa valores predeterminados, mantiene una caché y notifica cambios a suscriptores. Controla estados como Apple OAuth o actualizaciones de soporte donde el código los consume. Sus datos viven en este dispositivo. |
| [versioningService.ts](../../apps/referidos-android/src/shared/services/versioningService.ts) | Formatea versiones y traduce métodos de pantalla a acciones de `versioning-ops-proxy`. Expone catálogos, historial, drift, snapshots, releases, artefactos, nodos, sincronización y gates de despliegue/migraciones. Es el sitio para diagnosticar diferencias entre la acción enviada por Android y lo que espera el proxy runtime. |

Un ejemplo práctico es el escáner de negocio. `NegocioEscanerScreen` obtiene el negocio con `fetchBusinessByUserId`. Al recibir un QR, `redeemValidQrCode` envía la operación a una RPC y la pantalla refresca historial. Si el historial carga pero falla el canje, revisa primero la respuesta de RPC. Si ambos fallan, revisa primero sesión, ID del negocio y entorno. ## Estado, acceso y notificaciones

| Archivo | Qué hace y por qué existe |
|---|---|
| [appStore.ts](../../apps/referidos-android/src/shared/store/appStore.ts) | Estado raíz de sesión y onboarding. Usa `getSession`, el resultado de `onboarding` y los roles reconocidos para decidir acceso y verificación. Resetea estados al perder la sesión y maneja cierre de sesión y métodos de acceso disponibles. |
| [shellStore.ts](../../apps/referidos-android/src/shared/store/shellStore.ts) | Mantiene la pestaña activa por rol y un contador para desmontar el árbol anterior cuando se limpia la sesión. Preserva la posición dentro de la app durante cambios normales de pestaña. |
| [modalStore.ts](../../apps/referidos-android/src/shared/store/modalStore.ts) | Define modelos de confirmación, alerta y selector. Almacena el modal activo y funciones para abrir, cerrar o resetearlo. La pantalla aporta la acción específica y reutiliza el render del host. |
| [securityStore.ts](../../apps/referidos-android/src/shared/store/securityStore.ts) | Implementa máquina local de acceso con `LOCKED`, `UNLOCK_LOCAL` y `REAUTH_SENSITIVE`. Usa reglas de `security-core`, validez temporal y acciones pendientes. El desbloqueo local dura por defecto diez minutos y el sensible cinco. |
| [supportDeskStore.ts](../../apps/referidos-android/src/shared/store/supportDeskStore.ts) | Conserva el ID público del hilo seleccionado, de modo que inbox, router administrativo y ficha compartan el mismo puntero al abrir un ticket. |
| [localAccessSecurity.ts](../../apps/referidos-android/src/shared/security/localAccessSecurity.ts) | Adapta las reglas de PIN y acceso de `security-core` al almacenamiento/plataforma de `platform-rn`. Persiste PIN o biometría por identidad de Auth y refleja indicadores en la fila `usuarios`; separa `authUserId` del ID de tabla. Maneja intentos y desbloqueos e inicia reautenticación por correo, cuya confirmación sigue siendo local. |
| [useRoleNotifications.ts](../../apps/referidos-android/src/shared/hooks/useRoleNotifications.ts) | Carga, refresca y marca notificaciones como leídas. Según política monta un intervalo de polling y una suscripción Realtime a `app_notifications` y los desmonta en cleanup. Expone conteo sin leer, error, carga y acciones para los paneles. |
| [supportCategories.ts](../../apps/referidos-android/src/shared/constants/supportCategories.ts) | Catálogo estático tipado de motivos disponibles para el autoservicio de cliente y negocio, con audiencia y descripción. Lo importan sus pantallas de perfil. |
| [supportDesk.ts](../../apps/referidos-android/src/shared/constants/supportDesk.ts) | Define IDs, etiquetas y tipos de filtros del inbox por estado y origen. El bloque operativo de las macros se carga en runtime. |
| [env.ts](../../apps/referidos-android/src/shared/constants/env.ts) | Lee primero `env.json` y después variables disponibles en el proceso, normaliza comillas y valida URL/redirect. Concentra la selección de entorno y evita inicializar el cliente con parámetros vacíos. |
| [urlHermesPatch.ts](../../apps/referidos-android/src/shared/polyfills/urlHermesPatch.ts) | Prueba si la implementación de `URL` del runtime cubre la funcionalidad que usa Supabase y define un reemplazo parcial cuando hace falta. Admite URLs relativas y cambio de protocolo para Realtime. Se carga antes del cliente, desde `index.js`. |

## Límites que afectan el mantenimiento

- Las pantallas de pestaña están montadas con `lazy: false`. El lector nativo comprueba el permiso al montar y su condición de render considera permiso/error. Si ves consumo de cámara o red al cambiar de pestaña, revisa el ciclo de foco antes de ajustar el escaneo o los intervalos. [RoleTabs.tsx](../../apps/referidos-android/src/navigation/RoleTabs.tsx) · [NativeQrScannerBlock.tsx](../../apps/referidos-android/src/features/scanner/NativeQrScannerBlock.tsx)
- Aunque el panel muestre indicadores en `usuarios`, el material local de acceso pertenece al dispositivo. El cliente Supabase compartido configura PKCE y persistencia pero en la inicialización Android revisada no se le pasa un adaptador de almacenamiento de sesión explícito. Conviene comprobar el arranque tras reinicio real del proceso antes de dar por validada esa persistencia. [Inicialización Android](../../apps/referidos-android/src/shared/services/mobileApi.ts) · [Factory Supabase móvil](../../packages/api-client/src/clients/createSupabaseMobileClient.js)
- Ajustes de diagnóstico y acceso del repositorio, incluido el módulo API ignorado por Git, quedan en la [lista de pendientes](../09-pendientes-y-verificacion.md).
